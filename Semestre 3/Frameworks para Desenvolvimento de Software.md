## U1A1 - Conceitos e Definições
• Os frameworks são estruturas predefinidas cujo objetivo é
	facilitar o desenvolvimento de softwares.

### O que são
1. São coleções de códigos-fonte, classes, funções, técnicas e
	metodologias que dinamizam o desenvolvimento de softwares.
2. Chamados de Arcabouços de softwares – fornecem
	funcionalidade genérica, que pode ser configurada para
	específica.
3. Fazer Reuso.
4. Utilizados em grande escala por desenvolvedores.

### Characterísticas dos Frameworks
1. Abstração de dados
	• Fazer consultas em banco de dados, desconhecendo o seu
		armazenamento.
	• Recuperação de dados.

2. Polimorfismo
	• Classes derivadas invocam (chamam) métodos, da classe
		base (reutilização)

3. Herança:
	• Reutilização de códigos.
	• Classe derivadas herdam classes em entre si, se uma
		delas herdarem da classe base ou superclasse
		
### Diferença entre: Framework, API, Componentes e Plataformas
- Framework: 
	- Abstração de dados, reuso e Polimorfismo
	- Tipos: Suporte, aplicação, domínio.
	- Exemplos: React, Vue, Bootstrap, Angular
- API: 
	- Permite trocar dados, recursos entre aplicativos. 
	- Tipos: Privada ou Pública.
	- Exemplos: SOAP, REST
- Componentes: 
	- Reutilização de seus componentes para outros softwares.
	- Tipos: Interface com o usuário, serviço e domínio
	- Exemplos: REP – Reuse/Release Equivalence Principle 
- Plataformas: 
	- Servem como base para programar em uma determinada linguagem
	- Tipos: Nativas (sistemas específicos), Multiplataformas (cria-se aplicações para inúmeros sistemas).
	- Exemplos: NetBeans, GitHub, Bootstrap, Azure.
	
### Tipos de Frameworks 
• Para WEB(Django, Ruby, Lavarel).
• Para Mobile (Fluter, React, Native).
• Para Desktop (Electron e QT).
• Para Front-end (React, Angular).
• Para Back-end (Django).
• Para jogos (Unity e Unreal).

### Considerações Finais
- Benefícios:
	- Economia a longo prazo
	- Aproveitamento da experiência de especialistas do domínio
	- Maior consistencia e integração entre aplicações
	- Redução da manutenção: menos linhas de código nas aplicações
		reparos no framework se propagam pelas aplicações 
	- Melhora da produtividade: os programadores podem se concentrar
		nas caracteristicas especificas de suas aplicações.

- Custos:
	- Mais esforço para construção e aprendizado
	- Programas mais dificeis de depurar
	- Necessaria documentação de manutenção e apoio

## U2A1: Conceito de Framework - Spring 
- O Spring Framework é um framework voltado para o 
	desenvolvimento de aplicações corporativas para a 
	plataforma Java, baseado nos conceitos de inversão 
	de controle e injeção de dependências.
	
### Introdução, propósito e conceito sobre o Spring Framework.
- O Spring Framework é um ecossistema.
	- segue anexo: FDS_U2A1_ecosistema_spring.png
- Conjunto interconectado de tecnologias, ferramentas,
	comunidades e práticas que colaboram para atingir um objetivo
	comum, geralmente o desenvolvimento de software ou sistemas.

- Principais Modulos
	- Spring Boot: Ambiente para criação de aplicativos.
	- Spring Data: Facilita o acesso a banco de dados relacionais e não
		relacionais.
	- Spring Security: Framework para autenticação e controle de acesso.
	- Spring Cloud: Gerenciamento de configuração, roteamento
		inteligente, micro Proxy, barramento de controle.
	- Spring AI: Suporte para os principais provedores de IA como
		Anthropic, OpenAI, Microsoft, Amazon, Google e Ollama.
		
- Principais Subframeworks:
	- Spring Cloud Data Flow – orquestração de pipelines de dados em lote e streaming.
	- Spring Authorization Server – implementação de servidores de autorização OAuth2.
	- Spring for GraphQL – suporte a APIs GraphQL com integração ao Spring Boot.
	- Spring Session – gerenciamento de sessões independente do contêiner de servlet.
	- Spring Integration – integração de sistemas e padrões de mensagens.
	- Spring HATEOAS – criação de APIs REST com hipermídia.
	- Spring Modulith – suporte à construção de aplicações modulares.
	- Spring REST Docs – geração de documentação de APIs REST a partir de testes.
	- Spring Batch – processamento de dados em grandes volumes (batch processing).
	- Spring CLI – interface de linha de comando para criação rápida de projetos Spring.
	- Spring AMQP – suporte ao protocolo AMQP para mensagens assíncronas.
	- Spring CredHub – integração com o serviço de credenciais do Cloud Foundry.
	- Spring Flo – interface gráfica para construção de pipelines de dados.
	- Spring for Apache Kafka – integração com a plataforma Kafka de mensagens distribuídas.
	- Spring LDAP – acesso e integração com diretórios LDAP

### Arquitetura principal do Framework, componentes e tecnologias (JEE, DAO, MVC, dentre outras.
- JEE (Java Platform, Enterprise Edition).
	• Código aberto.
	• Java EE 8.
	• JSRs - Java Specification Request – Solicitação de Especificação Java.

- DAO (Data Access Object ou Objeto de Acesso a Dados)
	• Abstrair o acesso a fonte de dados (banco de dados);
	• Faz a leitura e gravação destes dados;
	• Encapsula os dados (agrupa informações).

- MVC (Model View Controller ou Controlador de Visualização de Modelo).
	• Framework web.
	• API Servlet (utilização da linguagem Java para criação de conteúdos
		dinâmicos (a partir de requisições HTTP), em servidores web.

### Integração entre Spring e as tecnologias de front-end.
- Spring MVC no Front-end:
	• Spring MVC permite renderizar páginas dinâmicas via templates.
	• Trabalha com @Controller, Model e View.
	• Permite retorno de páginas HTML com dados vindos do servidor:
	``` Java 
	@RequestMapping("/home")
	public String home(Model model) {
		model.addAttribute("nome", "Joao");
		return "home";
	}
	```

- Uso de Templates com Thymeleaf
	• Thymeleaf é um mecanismo de template compatível com Spring.
	• Permite interpolar variáveis no HTML:
	``` HTML 
	<h1>Bem-vindo, <span th:text="${nome}"></span></h1>
	```
	• Visual moderno e semântica HTML
	preservada

- Integração com Javascript e APIs
	• Front-end Spring pode integrar-se com APIs REST do próprio projeto.
	• Comunicação via AJAX com JSON.
	• Exemplo com Fetch:
	``` Javascript 
	fetch("/api/dados")
	.then(response => response.json())
	.then(data => console.log(data));
	```
- Organização e Estilo
	• CSS e JS organizados em /static ou /public.
	• Imagens em /resources.
	• Separação clara de responsabilidades melhora manutenção e
		colaboração entre equipes.
		
## U2A3 - Framework Spring - Mid-tier
• AOP melhora a legibilidade e manutenibilidade do código.
• APIs como AspectJ e JUnit promovem separação de interesses 
	e testes automatizados.

### APIs AOP - Aspectj, Pointcut, Advice, Proxy 
• AOP permite separar responsabilidades como logs,
	segurança e transações.
• APIs AOP e de testes fortalecem a qualidade do software.
• Importante em arquiteturas modernas como microsserviços.

- Fundamentos de AOP:
	• AOP = Programação Orientada a Aspectos.
	• Separa código transversal do núcleo da aplicação.
	• Usado para logs, auditoria, segurança e tratamento de exceções.

- APIs AOP: AspectJ:
	• AspectJ é a API mais usada em Java para AOP.
	• Pointcut: define onde o código será interceptado.
	• Advice: ação antes, depois ou ao redor de um método.
	• Proxy: intercepta chamadas e aplica os aspectos.

- Aplicações Práticas de AOP:
	• Logging automático sem alterar a lógica do sistema.
	• Controle de acesso e monitoramento de desempenho.
	• Exemplo: aplicação Spring Boot com @Aspect para monitorar 
		requisições.

### APIs para Teste: Unitários e integração.
- APIs de Teste:
	• JUnit: teste unitário em Java – métodos isolados.
	• Mockito: Mock de dependências – simula comportamentos.
	• Selenium/Postman: testes de integração – interface e APIs.

## U2A4 - Framework Spring - Back-end
• AOP (Programação Orientada a Aspectos) permite separar
	responsabilidades como logs, segurança e transações.
• Melhora a legibilidade e a manutenção do código.

- Fundamentos de AOP:
	• Permite modularizar crosscutting concerns (como logs e 
		autenticação).
	• Os aspectos interceptam métodos e adicionam comportamentos.
	• Usa o padrão Proxy para aplicar funcionalidades sem alterar 
		a lógica principal.

### AspectJ e Componentes
• AspectJ é a API AOP mais popular para Java.
• Pointcut: define onde aplicar o aspecto.
• Advice: ação aplicada (antes, depois ou ao redor).
• Proxy: intermedia a execução dos métodos interceptados.

### APIs para Testes 
- Testes Unitarios:
	• Testes unitários validam funções isoladas com ferramentas como JUnit.
	• São rápidos, precisos e escritos pelos próprios desenvolvedores.
	• Detectam falhas logo no início do ciclo de desenvolvimento.

- Testes de Integração:
	• Verificam a comunicação entre componentes (ex.: API ↔ banco).
	• Simulam cenários reais com ferramentas como Postman e Selenium.
	• Garantem que os módulos funcionem em conjunto.
	
### Resumo
- Conceito de Framework Spring:
	- O Spring é um framework de código aberto baseado na 
		linguagem Java, voltado para o desenvolvimento de 
		aplicações robustas, flexíveis e testáveis. Ele adota 
		princípios como injeção de dependência (DI) e inversão de 
		controle (IoC) para promover uma arquitetura desacoplada, 
		favorecendo a modularidade e a integração com outras 
		tecnologias. Empresas como a TOTVS, Bradesco e Petrobras 
		utilizam o Spring para aplicações financeiras, ERPs e 
		sistemas críticos de gerenciamento. O uso do Spring Boot, 
		uma extensão do Spring, permite criar microserviços 
		rapidamente com configurações mínimas, integração nativa 
		com bancos de dados e suporte a APIs REST.

- Framework Spring: Front-End
	- Embora o Spring não seja um framework de front-end no 
		sentido tradicional (como React ou Angular), permite a 
		construção de interfaces web server-side por meio de 
		módulos como Spring MVC (Model-View-Controller) integrados 
		a Thymeleaf ou JSP. Por exemplo, sistemas internos 
		corporativos desenvolvidos por empresas do setor público 
		e da indústria, como Serpro ou Embrapa, utilizam Spring 
		MVC com Thymeleaf para exibir dashboards, formulários e 
		relatórios diretamente renderizados no lado do servidor. 
		Essa abordagem é útil em aplicações monolíticas onde a 
		camada de visualização é acoplada ao controle de fluxo do 
		back-end, reduzindo a complexidade de integração com APIs 
		(Thymeleaf Documentation, 2024).

- Framework Spring: Mid-Tier
	- A camada mid-tier no Spring é responsável pela lógica de 
		negócio e orquestração de serviços. Nessa camada, o Spring 
		Core, Spring Context, Spring AOP e o Spring Security são 
		amplamente utilizados para implementar regras de negócio, 
		tratamento de exceções, controle transacional e 
		autenticação/autorização. Um caso prático é o da Stone 
		Pagamentos, que utiliza Spring no meio da arquitetura para 
		aplicar validações de pagamento, cálculos de taxas, 
		autenticação com tokens JWT e interceptação de chamadas 
		com AOP. Essa separação de responsabilidades aumenta a 
		manutenibilidade e a testabilidade do sistema.

- Framework Spring: Back-End
	- No back-end, o Spring se destaca por meio de módulos como 
		Spring Data JPA, Spring JDBC, e Spring Boot Data REST, que 
		facilitam a persistência de dados e exposição de APIs. 
		Empresas como a Localiza utilizam Spring Data JPA com 
		Hibernate para persistir dados de clientes, reservas e 
		veículos. A facilidade para criar repositórios com métodos
		automáticos (findByNome, findByCpf) acelera o 
		desenvolvimento e reduz a necessidade de escrever SQL 
		manual. Com Spring Boot + Spring Web, é possível expor 
		APIs RESTful com alta performance e segurança, integradas 
		com ferramentas como Swagger, OAuth 2.0 e OpenID Connect, 
		como fazem sistemas financeiros e plataformas SaaS no Brasil.

- Portanto, o Spring Framework é um dos mais poderosos e 
	amplamente adotados frameworks no mercado corporativo para 
	desenvolvimento em Java. Sua arquitetura permite separar
	responsabilidades entre front-end (Spring MVC com Thymeleaf), 
	mid-tier (lógica de negócio, segurança, controle transacional)
	e back-end (persistência e APIs REST). Empresas que seguem 
	essa estrutura em camadas obtêm ganhos em organização, 
	produtividade, testabilidade e escalabilidade.

• Ideal para projetos Java com foco em clareza e organização

### Arquitetura 
• Componentes: SessionFactory, Session, Transaction.
• Integra-se com JDBC e JEE, suportando SE e EE.
• Promove separação entre lógica de negócio e dados.

- SessionFactory:
	- Cria e gerencia instancias de sessão para interações
		com o banco de dados 

- Session:
	- Controla transações e interage com entidades Java.
	
- Transaction:
	- Gerencia operações e commit e rollback para integridade
		dos dados.
	
- Java Entities:
	- Representa objetos de dados manipulados pelo Hibernate
	
- ORM Mapping:
	- Conecta entidades Java a tabelas de banco de dados 
		relacionais.
	
- Persistence Cycle:
	- Descreve o ciclo de vida das operações de dados
		no Hibernate.
	
### Configuração
• Criar POJOs com anotações: @Entity, @Id, @Column.
• Definir hibernate.cfg.xml com conexões JDBC.
• Integrar com Spring, Java EE ou standalone.

### Mapeamento Objeto-Relacional (ORM)
• Classes Java ↔ Tabelas | Atributos ↔ Colunas.
• Relacionamentos via @OneToMany, @ManyToOne, etc.
• Exemplo: xliente com lista de Pedido

### Criação Automática de Tabelas
• Gera o banco com hbm2ddl.auto = update.
• Facilita a criação e sincronização entre código e 
	banco de Dados 
``` Java
@Entity
public class Cliente {
	@Id
	@GeneratedValue
	private Long id;
	private String nome;

	@OneToMany(mappedBy = "cliente")
	private List<Pedido> pedidos;
}

@Entity
public class Pedido {
	@Id
	@GeneratedValue
	private Long id;
	private String descricao;

	@ManyToOne
	@JoinColumn(name = "cliente_id")
	private Cliente cliente;
}
```

## U3A2 - Consultas em Framework - Hibernate

• Promove organização, portabilidade e produtividade.
• É amplamente usado em aplicações Java comerciais.

### Controle de transações no HQL: gerenciamento e filtragem de dados

- O Hibernate Query Language (HQL) é a linguagem de consulta 
	orientada a objetos do Hibernate, projetada para operar sobre 
	as entidades e seus atributos ao invés das tabelas e colunas 
	do banco. Utilizar HQL permite que desenvolvedores escrevam 
	consultas de maneira mais próxima do domínio da aplicação, 
	mantendo a lógica centrada nos objetos. Diferente do SQL 
	tradicional, o HQL interpreta as classes e não diretamente as 
	tabelas, o que proporciona uma camada de abstração útil e 
	segura para a manipulação de dados.

- Fluxo de Controle de Transação do Hibernate
	- OpenSession() -> beginTransaction() -> 
	- -> createQuery("from Entidade where campo = :valor") ->
	- -> setParameter("valor", objetoOuValor) -> commit()
	

- SQL Nativo e Performance
	- Embora o HQL seja mais alinhado à filosofia orientada a 
		objetos do Hibernate, existem situações em que o uso de 
		SQL nativo (Native SQL) é preferível ou até necessário. 
		Isso ocorre principalmente em casos de consultas 
		extremamente específicas ou otimizadas, que fazem uso 
		de recursos particulares do banco de dados, como funções
		de agregação avançadas, índices específicos ou joins 
		complexos que seriam difíceis de expressar em HQL.

• Banco pode ser criado a partir do modelo com Hibernate Tools

### Conceito de Activity e Ciclo de Vida
• Activity é a unidade de interface no Android.
• A entrada e saída de dados entre telas ocorre via Intent.
• Ciclo de Vida:
	1. onCreate() : inicialização da activity e carregamento
	   da interface
	2. onStart() : activity se torna visível
	3. onResume() : activity em primeiro plano
	4. onPause() : outra activity ganha foco 
	5. onStop() : activity não está mais visível 
	6. onRestart() : retorno do onStop()
	7. onDestroy() : destruição da activity

### Eventos e Interações
• Eventos como clique, rotação e toque são capturados por 
	Listeners (onClickListener, onTouchListener).
• Manipular o ciclo corretamente evita falhas e melhora a 
	experiência do usuário.

• Estrutura MVC nativa.
• ORM integrado e painel administrativo automático.

### Outros Frameworks Python
• Django: framework completo que utiliza o padrão MTV 
	(Model-Template-View), focado em produtividade, segurança 
	e escalabilidade. Ideal para aplicações robustas como redes 
	sociais, sistemas de gestão e plataformas de e-commerce.
• Flask: microframework conhecido por sua simplicidade e 
	flexibilidade. Muito usado para APIs RESTful, aplicações leves

• Web2py: framework completo, de fácil configuração, com foco 
	em segurança e produtividade. Vem com IDE web integrada e 
	suporte nativo a múltiplos bancos de dados.
• CherryPy: framework minimalista que transforma qualquer 
	script Python em um servidor web funcional, sendo indicado 
	para aplicações que requerem controle total do desenvolvedor.
• Bottle: outro microframework que permite o desenvolvimento 
	de pequenas aplicações web com poucas linhas de código, 
	ideal para prototipagem e sistemas embarcados.

### Principais funções das Frameworks 
• Roteamento: interpretação das URLs e direcionamento para 
	funções específicas.
• ORM: mapeamento objeto-relacional para manipular dados sem 
	escrever SQL.
• Templates: geração dinâmica de páginas HTML com dados vindos 
	do back-end.
• Middleware e segurança: camadas intermediárias que controlam 
	acesso e tratamento de requisições.
• Geradores de CRUD: automatizam formulários, validações e 
	interfaces administrativas.

### Frameworks versus Micro Frameworks
• Frameworks completos: oferecem ORM, templates, rotas e
	segurança nativamente.
• Microframeworks: leves e flexíveis; exigem bibliotecas 
	externas.
